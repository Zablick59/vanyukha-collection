# ВАНЮХА collection's

Личная коллекция фильмов, сериалов и игр. Основная онлайн-версия рассчитана на **бесплатные Cloudflare Workers + D1**, а PlayStation обновляется через GitHub Actions. Отдельная Python-версия служит для локального просмотра и проверки миграции.

## Что работает

- Публичная коллекция, поиск, сортировка, фильтр PC / PlayStation и список планов.
- `/admin`: один владелец, вход по паролю, добавление, редактирование и удаление.
- Вход сохраняется на устройстве на 90 дней и продлевается при открытии админки или возвращении в неё. «Выйти» удаляет облачную сессию на сервере; смена пароля отзывает все сессии. Сам пароль в браузере приложение не сохраняет.
- Админку можно добавить на главный экран iPhone: Safari → «Поделиться» → «На экран Домой» → «Добавить» (если есть переключатель «Открыть как веб-приложение», оставить его включённым). Открыть новую иконку и войти один раз. У приложения своя иконка и запуск прямо в `/admin`; для работы нужен интернет.
- Короткий комментарий и отдельная необязательная рецензия. Вкладка «Рецензия» появляется только у записей с рецензией; тексты сохраняются независимо. Последние записи в админке идут от последних добавленных, независимо от даты просмотра и редактирования.
- Оценки с запятой или точкой, быстрые кнопки 1–10, дата и впечатления.
- Постеры: поиск Wikipedia без ключа, необязательный TMDB, загрузка JPEG/PNG/WebP с устройства. Браузер уменьшает картинку, сохраняет JPEG до 500 КБ и удаляет исходные метаданные.
- Сохранение в общую онлайн-базу сразу; открытая публичная страница перечитывает данные каждые 30 секунд и при возвращении на вкладку.
- PlayStation: проверка ежедневно около 08:17 по Екатеринбургу, получение статистики только раз в 7 дней или по запросу владельца. Расписание GitHub иногда задерживается. Для немедленного запуска есть ссылка на **Actions → PlayStation weekly sync → Run workflow**.
- Повторный запуск не прибавляет часы повторно. Сохраняются оценки, постеры и часы Steam; названия сопоставляются с учётом известных суффиксов изданий.
- Ошибки PSN видны в админке. Истёкший NPSSO можно заменить там же.

## Посмотреть на этом компьютере

Двойной щелчок по `start.command`: публичная страница `http://127.0.0.1:8000`, админка `/admin`. Это локальный просмотр, он не открывает доступ с телефона через интернет. Пароль записан в `.local/owner-access.txt`; файл исключён из Git. Для смены локального пароля: `.venv/bin/python setup_owner.py`, затем перезапустить локальный сервер.

Для проверки именно Cloudflare-версии нужны Node.js 22+ и pnpm:

```sh
pnpm install
node scripts/setup_cloudflare.mjs
node scripts/build.mjs
pnpm exec wrangler d1 execute vanyukha-collection --local --file cloudflare/schema.sql
pnpm exec wrangler d1 execute vanyukha-collection --local --file .local/cloudflare-import.sql
pnpm dev
```

Она доступна на `http://127.0.0.1:8787`. Локальная D1-база сохраняется в `.wrangler/`. Python-просмотр и локальная D1 — отдельные копии; после публикации общим источником данных является удалённая D1.

## Бесплатная публикация (один раз)

1. Войти в собственный аккаунт Cloudflare: `pnpm exec wrangler login`. Нужен аккаунт Free, подключение платного Workers не требуется.
2. Создать D1: `pnpm exec wrangler d1 create vanyukha-collection`. Внести возвращённый `database_id` в `wrangler.jsonc` вместо нулевого значения.
3. Создать таблицы и **однократно** перенести текущие данные:

   ```sh
   pnpm exec wrangler d1 execute vanyukha-collection --remote --file cloudflare/schema.sql
   pnpm exec wrangler d1 execute vanyukha-collection --remote --file .local/cloudflare-import.sql
   ```

   При развёртывании из чистого Git вместо частного импорта использовать `seed/collection.sql`; первоначальная PSN-синхронизация установит точки отсчёта. При обновлениях сайта повторный импорт не нужен.

4. Подготовить приватные настройки командой `node scripts/setup_cloudflare.mjs`, затем загрузить их в **Worker Secrets**, не в исходники:

   ```sh
   pnpm exec wrangler secret bulk .local/cloudflare-secrets.json
   pnpm deploy
   ```

   Файл содержит `APP_SECRET`, `OWNER_PASSWORD_HASH`, `PSN_SYNC_SECRET`, `PSN_NPSSO`. Он исключён из Git. `APP_SECRET` нельзя менять без переноса зашифрованных настроек: иначе сохранённые в админке ключи перестанут читаться. Пароль владельца тот же, что в локальном файле доступа. Для его замены создать новый PBKDF2-хэш и обновить только Worker Secret `OWNER_PASSWORD_HASH`; предыдущие сессии сразу потеряют доступ.

5. В GitHub → репозиторий → **Settings → Secrets and variables → Actions** сохранить только:
   - `SITE_URL` — выданный HTTPS-адрес `https://vanyukha-collection.<твой-поддомен>.workers.dev` без `/admin`;
   - `PSN_SYNC_SECRET` — одноимённое значение из частного файла Cloudflare Secrets.
6. Workflow `.github/workflows/psn-sync.yml` должен попасть в default branch репозитория. Запустить вручную и проверить успешное завершение и состояние PSN в админке. Еженедельная автоматика не считается включённой до этой проверки.
7. Использовать новый Cloudflare-адрес на телефоне. Перенаправление со старого GitHub Pages-адреса можно добавить после получения нового адреса.

## Безопасность и Git

В браузере не хранится GitHub-токен или NPSSO. Сессия — случайный токен в HttpOnly/Secure/SameSite-cookie; сервер хранит его хэш. Все изменения проверяют Origin, CSRF и владельца. Пароль хранится как PBKDF2-хэш; перебор ограничен. Ключи, введённые через админку, зашифрованы AES-GCM в D1. Служебный канал PSN доступен только по отдельному секрету Actions.

`.gitignore` исключает `.env`, `.dev.vars`, `.local`, `.wrangler`, SQLite-базы, ключи, выгрузки CSV, кэши, зависимости и системный мусор. Рабочий каталог целиком не раздаётся: публичные файлы сборки находятся только в `dist/`.

Игнорирование не убирает ранее опубликованные файлы из истории Git. В локальной истории из 37 коммитов существующий NPSSO не обнаружен. Старые CSV и `psn_cache.json` присутствуют в старой истории; новый коммит убирает их из текущего дерева, но не переписывает историю. Если позже будет обнаружен опубликованный секрет, сначала отозвать его, затем отдельно очищать историю.

## Проверки и резервные копии

```sh
node --test tests/worker.test.mjs
.venv/bin/python -m unittest discover -s tests -v
```

Проверены доступ без входа, CSRF, чужой Origin, вход/выход, сохранение/редактирование, конфликт версий, валидация, загрузка постера, скрытие ключей, повторная синхронизация, сброс счётчика часов, похожие названия, недельное расписание и лимит запросов D1 Free. Интерфейс просмотрен на 390 и 320 пикселях и на компьютере. Облачная версия проверена по публичному адресу. GitHub workflow ещё требует загрузки и контрольного запуска.

Кнопка «Скачать коллекцию» сохраняет публичные карточки. Полную базу с постерами и приватными настройками резервировать отдельно:

```sh
pnpm exec wrangler d1 export vanyukha-collection --remote --output .local/d1-backup.sql
```

Этот дамп конфиденциален. В D1 Free также есть Time Travel за последние 7 дней. Локальная Python-версия делает до 7 снимков SQLite перед синхронизацией.

## Границы бесплатного тарифа

Workers Free: 100 000 запросов в сутки; D1 Free: 5 млн прочитанных строк и 100 000 записей в сутки, до 500 МБ на базу. Карточки с внешними постерами почти не занимают место; собственные постеры занимают место в D1. При достижении лимита Free операции могут остановиться; платный тариф автоматически не подключается этим проектом. Для обычной личной коллекции эти лимиты выглядят достаточными, но реальный расход зависит от посещаемости.
